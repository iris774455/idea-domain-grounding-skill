# idea-domain-grounding

面向轻量级跨学科设想的领域知识识别、主动降维、概念对齐与 AI 上下文固化 Skill。

## 目标（Goals）

在轻量级跨学科设想正式进入架构设计或编码实现前，帮助人机双方先对齐“要解决什么问题、涉及哪些专业知识、哪些复杂度应该主动绕开”，并将其固化为高信噪比、可长期引用的纯 Markdown AI 上下文基座：

1. **理清系统边界**：隐性借用问题框架（`W, S ⊢ R`），区分系统恒定目标（`R`）、自身职责（`S`）、外部前提（`W`）与主动裁剪的非目标（`Non-Goals`），防止后续开发不断扩 scope。
2. **识别依赖与主动降维**：按共享现象边界将涉及领域划分为 `核心依赖`、`接口级引用` 与 `黑盒降维` 三档介入深度，严防伪降维，优先绕开非核心复杂度。
3. **跨学科概念排歧**：借助本体分类（实体 / 过程 / 规范 / 关系），为关键术语建立带稳定 ID（`T-xx`）的唯一定义与“不是什么 / 勿混淆为”排歧说明，避免跨领域同名异义造成 AI 理解偏差。
4. **沉淀防跑偏 AI 基座**：通过稳定编号（`T-xx` / `IF-xx` / `INV-xx`）、两阶段确认门控与按需分层结构，降低长对话中的上下文遗忘、幻觉脑补与静默回归风险。

## 使用场景（Use Cases）

### 适用场景

- **新点子与跨领域小工具**：提出模糊创意或跨学科项目设想时，希望快速理清涉及的专业领域与介入深度。
- **觉得想法太复杂想做减法**：需要主动裁剪需求边界、确定哪些部分可直接用现成工具或规则“黑盒降维”。
- **跨学科术语对齐**：项目横跨多个领域（如业务规则、算法、硬件、教育、设计等），容易出现同名异义或概念混淆，需要统一词表与跨领域接口契约。
- **写代码前为 AI 建项目底座**：希望在正式编码前生成一份结构化上下文文档，让后续的 AI 助手严格遵循既定定义与硬约束，不擅自扩需求或从零造轮子。
- **已有基座的增量迭代与分层深化**：当单文件基座在多轮迭代中出现上下文摩擦或局部规则复杂化时，按需演进为 `L0 + L1` 分层规格文档。

### 不适用场景

- 纯软件工程编码规范或单学科 AI 提示词文档（如 `AGENTS.md`）
- 已有定稿规格的纯文档整理，或需求已完全明确、可直接动工的开发任务
- 重型商业立项报告或正式合规审计
- 纯单学科常规问答

## 核心工作流与产出形态

### 两阶段确认门控

- **阶段一（对话草案与确认）**：默认不直接落盘文件，而是先输出单屏草案（目标与边界、候选领域清单、降维建议）以及 2–4 个带推荐项与得失对比的确认问题；增量迭代时则输出受影响目标/ID 的 diff 草案与确认问题。
- **阶段二（固化交付）**：根据确认结果交付遵循小写短横线 slug 命名的纯 Markdown 文档。

### 渐进式文档结构

1. **早期单文件（默认，零流程税）**：`<project-slug>-domain-context.md`
   - 包含目标与系统边界、跨学科概念对齐表（`T-xx`）、领域知识依赖与降维地图、跨领域接口与客观硬约束（`IF-xx` / `INV-xx`），以及可选的待验证假设。
2. **深化期分层（按需触发）**：`L0` + `L1`
   - 仅当出现上下文摩擦（`TRG-01`）、局部深化（`TRG-02`）或回归失稳（`TRG-03`）信号且经确认后升级：
     - **L0 路由地图**（`<project-slug>-map.md`，≤100 行）：作为长对话唯一常驻入口，索引恒定目标 `R`、受控术语、全局 `IF/INV` 及任务路由表。
     - **L1 领域深化子文档**（`<project-slug>-domain-<domain-slug>.md`，≤80 行）：按路由单次仅挂载 1 份，包含专业机制表、精简动作契约（`ACT-xx`）与只读契约边界用例（`golden_cases`）；具体工程参数或明细按需外置到 `specs/` 或 `references/` 并以带状态指针锚定。
   - 当项目范围收缩时，亦支持确认后合并回退为早期单文件形态。

## 文件说明

- `SKILL.md`：`idea-domain-grounding` 的完整 Skill 规范与执行约束
- `README.md`：使用场景、设计目标与结构说明

## 使用方式

将本仓库克隆或其中的 `SKILL.md` 复制到你所用 Agent 工具对应的 Skills 目录中即可（如 `~/.gemini/skills/idea-domain-grounding/` 或对应插件的 `skills/idea-domain-grounding/` 目录），在提出跨学科新点子、想收敛范围或准备建立项目上下文基座时触发使用。
